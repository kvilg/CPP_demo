# qt — мониторинг сигнала: эмулятор и регистратор

Два приложения, которые работают только в паре. Это реализация тестового
задания на вакансию инженера-программиста C/C++ (ООО «Инобитек»).

---

## Что требовалось по заданию

Разработать простую программную систему из двух приложений на Qt для
мониторинга **регулярного непрерывного сигнала** с воображаемого
источника.

**Приложение 1 — Эмулятор (сервер).** Непрерывно генерирует сигнал
программно и передаёт его транспортом TCP/IP по произвольному протоколу.

**Приложение 2 — Регистратор (клиент).** Принимает и отображает сигнал
средствами Qt, в текстовом или графическом виде.

Отдельно оговорено:

- интуитивно понятная интерактивность оконного интерфейса с динамическим
  отображением изменяющегося сигнала в центральном представлении;
- графическое представление приветствуется, и для него нужен набор
  стандартных инструментов управления просмотром: **масштабирование**,
  **управление отдельно амплитудой и периодом сигнала**, **выбор толщины
  сигнальной кривой** и **выбор цвета**;
- всё в форме Qt-проекта с исходниками.

## Что сделано, а что нет

| Требование | Состояние |
|---|---|
| Два приложения, эмулятор и регистратор | есть: [TcpServer](TcpServer) и [QtWidgetsDemo](QtWidgetsDemo) |
| Передача по TCP/IP, протокол произвольный | есть: число в строке, строки разделены `\n` |
| Графическое представление в центре окна | есть: `QChartView` с `QLineSeries` |
| Динамическое отображение | есть: окно просмотра едет за последними точками |
| Выбор цвета кривой | есть: кнопка «Выбрать...» и `QColorDialog` |
| **Регулярный непрерывный сигнал** | **нет: эмулятор шлёт `std::rand() % 50`, то есть шум** |
| **Управление амплитудой и периодом** | **нет** |
| **Масштабирование** | **нет: оси подстраиваются сами, вручную не управляются** |
| **Выбор толщины кривой** | **нет** |

Три незакрытых пункта связаны между собой, и корень у них один. У
случайных чисел **нет ни амплитуды, ни периода**, поэтому управлять
нечем. Пока эмулятор не начнёт выдавать настоящий сигнал — скажем,
синусоиду с задаваемыми амплитудой и периодом, — эти требования
реализовать невозможно.

Так что порядок работ выходит такой:

1. Сделать в эмуляторе регулярный сигнал вместо `std::rand()`.
2. Добавить в регистратор управление его амплитудой и периодом.
3. Добавить масштабирование и толщину кривой.

Заготовка под это в интерфейсе уже есть: в `QtWidgetsDemo/src/main.cpp`
создаётся `QLineEdit("1")` с именем `test`, который кладётся в панель, но
никуда не подключён — похоже, задумывался как раз под один из этих
параметров.

## Запуск

По отдельности обе программы бесполезны: эмулятор шлёт числа в пустоту,
регистратор рисует пустой график. Поэтому есть цель, которая поднимает
обе — и не требует второй копии IDE:

```powershell
.\build.ps1 -Demo
```

То же напрямую через CMake:

```powershell
cmake --build --preset debug --target run_demo
```

Эмулятор откроется в отдельном окне консоли, регистратор — следом.
Дальше в его окне нажать «Подключиться»: поля адреса и порта уже
заполнены под эмулятор, `127.0.0.1:1234`.

Под отладчиком так не выйдет — цель запускает программы без него. Для
отладки по-прежнему нужны два запуска.

---

## Как они связаны

| Эмулятор | Регистратор |
|---|---|
| `server.listen(QHostAddress::Any, 1234)` | поля по умолчанию `127.0.0.1` и `1234` |
| `QByteArray::number(std::rand() % 50) + "\n"` раз в секунду | `data.split('\n')`, `toDouble`, `addPoint(y)` |

Протокол — самый простой из возможных: десятичное число текстом, перевод
строки как разделитель записей. Заданием это и допускается: «по
произвольному протоколу».
