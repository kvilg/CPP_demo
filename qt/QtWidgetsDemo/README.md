# QtWidgetsDemo — регистратор сигнала

Приложение 2 из [задания](../README.md): подключается по TCP к эмулятору
[TcpServer](../TcpServer), принимает поток чисел и рисует их графиком в
центре окна. Весь интерфейс собран **целиком на виджетах** — один файл
`src/main.cpp`, без QML и без своих классов.

---

## Что из требуемого есть

| Требование задания | Состояние |
|---|---|
| Графическое представление в центре окна | `QChartView` с `QLineSeries` |
| Динамическое отображение | окно просмотра едет за последними точками |
| Выбор цвета кривой | кнопка «Выбрать...» и `QColorDialog` |
| **Масштабирование** | **нет**, оси подстраиваются только сами |
| **Выбор толщины кривой** | **нет**, хотя проводка готова |

Амплитуды и периода в таблице нет намеренно: это параметры генерации,
и задаются они в [эмуляторе](../TcpServer). Регистратор сам сигнал не
меняет — рисует то, что пришло, и даёт разглядывать это мышкой.

Толщина почти бесплатна: `RealTimePlot::setCurveColor` уже берёт
текущее перо и сохраняет его ширину, не хватает `pen.setWidth` и
контрола рядом с выбором цвета. Подробнее в
[qt/README.md](../README.md).

Заготовка под это в коде уже лежит: `QLineEdit("1")` с именем `test`
добавлен в панель, но ни к чему не подключён.

## Запуск

Вместе с эмулятором, из корня репозитория:

```powershell
.\build.ps1 -Demo
```

Дальше нажать «Подключиться» — поля адреса и порта заполнены под
эмулятор, `127.0.0.1:1234`. Без него график останется пустым.

Только регистратор:

```powershell
.\build.ps1 -Run QtWidgetsDemo
```

## Про сравнение с QML

Ниже интерфейс сравнивается с проектом QtDemo, где то же самое сделано
на QML. Самого QtDemo в этом репозитории нет, он остался отдельно, так
что таблицу соответствий и раздел про отличия читай просто как «как это
выглядело бы на QML».

---

## Соответствие QML и Widgets

| QML | Widgets |
|---|---|
| `ApplicationWindow` | `QMainWindow` |
| `header: ToolBar` | `QWidget` в общем `QVBoxLayout` |
| `footer: ToolBar` | `statusBar()` |
| `ColumnLayout` | `QVBoxLayout` |
| `RowLayout` | `QHBoxLayout` |
| `Item { Layout.fillHeight: true }` | `addStretch(1)` |
| `Label { ... }` | `QLabel` + `setStyleSheet()` |
| `Button { onClicked: ... }` | `connect(&QPushButton::clicked, ...)` |
| `value: controller.counter` | лямбда, которая обновляет виджет |

---

## Три отличия от QML

**Layout не занимает место сам.** Виджет создаётся без родителя, а
`addWidget()` сам его вставляет. Забудешь вызвать — окно будет пустым,
но программа не упадёт.

**Привязок нет.** В QML `value: controller.counter` перерисовывалось само.
Здесь обновляем виджеты вручную из лямбды:

```cpp
auto refresh = [&] {
    counterValue->setText(QString::number(counter));
    status->setText("Счётчик: " + QString::number(counter));
};

QObject::connect(plus, &QPushButton::clicked, [&] { ++counter; refresh(); });
```

**Карточки — лямбда.** `makeCard()` собирает виджет с подписью и
значением. Вместо отдельного класса ради двух `QLabel` внутри `QFrame`.

## Что можно добавить

Класс `AppController` вместо переменной `int counter` — если захочешь
отделить логику от интерфейса, как в `QtDemo`.

Свой виджет вместо `makeCard()` — чтобы переиспользовать карточку
в нескольких окнах.

`QSplitter` — две панели, которые тянутся мышью.
