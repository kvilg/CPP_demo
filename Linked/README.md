# Linked — двусвязный список своими руками

Шаблонный `List<T>` на сырых `new`/`delete`, с узлами, связанными в обе
стороны. Тесты на [doctest](https://github.com/doctest/doctest) лежат
в том же `List.cpp`, рядом с реализацией.

---

## Что уже работает

| Метод | Что делает |
|---|---|
| `addLast(value)` | добавить в конец |
| `addStart(value)` | добавить в начало |
| `getSize()` | количество элементов |
| `getValue(index)` | значение по индексу, **без проверки границ** |
| `setValue(index, value)` | заменить значение по индексу |
| `swap(other)` | обменяться содержимым, `noexcept` |
| `List(const List&)` | копирование, глубокое |
| `operator=(const List&)` | присваивание через copy-and-swap |
| `~List()` | освобождает все узлы |

---

## Что надо реализовать

Это и есть задание. Методы объявлены в `List.h`, заглушки в `List.cpp`
бросают `std::logic_error`, а тесты с именами `exercise: ...` падают.
Задача — написать тело и довести тест до зелёного.

| Метод | Подсказка |
|---|---|
| `isEmpty()` | разминка |
| `clear()` | освободить узлы, список остаётся пригодным для вставки |
| `removeStart()` | убрать первый |
| `removeLast()` | убрать последний |
| `insert(index, value)` | `index == getSize()` — это `addLast` |
| `removeAt(index)` | убрать элемент по индексу |
| `at(index)` | как `getValue`, но с проверкой границ и `std::out_of_range`; и, в отличие от него, `const` |
| `operator==` | сравнение по содержимому |
| `List(List&&)` | забрать содержимое, оставить источник пустым и валидным |
| `operator=(List&&)` | то же плюс освободить своё и не сломаться на self-move |
| `List(std::initializer_list<T>)` | чтобы работало `List<int> list{1, 2, 3}` |
| `operator=(std::initializer_list<T>)` | пара к нему, чтобы работало и `list = {1, 2, 3}` |
| свободный `swap(a, b)` | чтобы работал идиом std::swap two-step: `using std::swap; swap(a, b)` |
| `getStart()` / `getLast()` | первый и последний за O(1), по две версии: `T&` и `const T&` |
| `removeValue(value)` | удалить все равные |
| `reverse()` | развернуть порядок, не копируя и не меняя значения |
| `sort()` | отсортировать по возрастанию; `std::sort` сюда не подходит |
| `operator<=>` | C++20: одно сравнение, а `<`, `>`, `<=`, `>=` выведутся сами. Категорию возвращай как `std::compare_three_way_result_t<T>`: у `int` это строгий порядок, у `double` — частичный, из-за NaN |
| `assign(count, value)` / `assign({...})` | заменить всё содержимое |
| `resize(count)` / `resize(count, value)` | укоротить с конца или добить до длины; версия без значения требует от `T` конструктора по умолчанию |
| `unique()` | убрать **подряд идущие** дубликаты; чтобы убрать все, сначала `sort()` |
| `merge(other)` | слить два отсортированных, перецепив узлы; `other` опустеет |
| `emplaceLast(args...)` / `emplaceStart(args...)` | сконструировать элемент прямо в узле, без временной копии — perfect forwarding |
| `begin()` / `end()` и класс `Iterator` | чтобы заработало `for (int x : list)`; двунаправленный, значит и `operator--` |

**Про границы.** Всё, что в таблице выше, при выходе за границы и на
пустом списке бросает `std::out_of_range`. Исключения два — `getValue` и
`setValue`, они намеренно без проверок, как `operator[]` у вектора.
`std::list` в этих случаях выбирает UB, то есть скорость; мы выбираем
проверяемость, потому что на брошенное исключение можно написать тест,
а на UB нельзя.


`List(List&&)` и `operator=(List&&)` — это **правило пяти**: раз у класса есть деструктор и
копирование, перемещение тоже должно быть, иначе компилятор его не
сгенерирует и каждый возврат списка из функции будет копией.
`clang-tidy` ровно на это и ругается.

& $t -ltc                     # список всех тестов
& $t -tc="*isEmpty*"          # прогнать один
& $t -tc="exercise*"          # все упражнения

& $t -s                       # печатать и успешные проверки

### Две шероховатости

Русские имена тестов в консоли Windows превращаются в кракозябры:
`ctest` пишет их в UTF-8, а консоль читает в CP866. На результат не
влияет, но фильтровать по русскому имени неудобно — поэтому у
упражнений латинский префикс `exercise:`.

Если `Linked_tests.exe` запускается не через `build.ps1`, ему нужны
рантаймовые DLL MinGW в `PATH` (`libstdc++-6.dll`, `libgcc_s_seh-1.dll`,
`libwinpthread-1.dll`). Без них запуск молча падает с кодом 127, и так
же падает шаг перечисления тестов на этапе сборки. Лечится либо
`$env:Path = "C:\Qt\Tools\mingw1310_64\bin;$env:Path"`, либо статической
линковкой `-static-libstdc++ -static-libgcc`.

## Как устроено

**Тесты в том же `.cpp`, что реализация** — так задуман doctest, это его
главное отличие от gtest и Catch2. В цели `Linked` они вырезаются
препроцессором:

```cmake
target_compile_definitions(Linked PRIVATE DOCTEST_CONFIG_DISABLE)
```

`TEST_CASE` раскрывается в ничего, в программу не попадает ни тестовый
код, ни `main()` из doctest. Цель `Linked_tests` собирает тот же файл без
этого определения, а `main()` берёт из `doctest_with_main`.

**`Node` объявлен, но не определён в заголовке.** В `List.h` стоит только
`class Node;` — указателю на неполный тип определение не нужно, поэтому
`m_head` и `m_tail` работают, а устройство узла видно лишь в `List.cpp`.

Для шаблона так можно именно здесь, потому что инстанцирование одно и
лежит в том же `.cpp`:

```cpp
template class List<int>;
```

Компилятору негде увидеть `List<U>` для другого `U`, а значит и `Node`
там не понадобится. Поэтому **тесты есть только для `List<int>`**: нужен
`List<std::string>` — добавь рядом вторую строку инстанцирования.

### Потрогать руками

Есть цель, которая намеренно **не собирается** — [main_double.cpp](main_double.cpp):

```powershell
cmake --build --preset debug --target Linked_double
```

Она берёт `List<double>`, а инстанцирован только `List<int>`, и падает так:

```
undefined reference to `List<double>::addLast(double const&)'
```

Главное в этой ошибке — что она **от линковщика, а не от компилятора**.
Объявлений из `List.h` хватило, чтобы выпустить вызовы; тел не нашлось.

Цель помечена `EXCLUDE_FROM_ALL`, поэтому обычная сборка её не трогает и
остаётся зелёной — собирать только вручную, командой выше.

Чинится двумя взаимоисключающими способами, и выбор между ними и есть
смысл упражнения:

1. дописать `template class List<double>;` — минута, но каждый тип
   руками;
2. перенести реализацию в `List.h` — заработает любой тип, но `Node`
   придётся вернуть в заголовок и потерять его скрытность.

## Что можно сделать дальше

Когда все 35 тестов зелёные:

- **итераторы** `begin()`/`end()`, чтобы работал `for (int x : list)` и
  алгоритмы из `<algorithm>`;
- **`operator[]`** в двух версиях, `const` и неконстантной, возвращающей
  `T&` — тогда `list[0] = 5` заработает;
- **`emplace_back`** с perfect forwarding вместо `const T&`;
- **перенести реализацию в заголовок** и отказаться от явного
  инстанцирования — тогда список заработает с любым типом, но `Node`
  перестанет быть скрытым: за всё платят;
- **заменить сырые указатели** на `std::unique_ptr` и посмотреть, что
  станет с деструктором и `clear()`.
